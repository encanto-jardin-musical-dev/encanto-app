## Why

Users currently receive **two push notifications** for every new message when the app is in the background. The root cause is that the Edge Function sends an FCM payload that includes both a `notification` block and a `data` block: Chrome/FCM auto-displays the `notification` block directly, and then `onBackgroundMessage` in `firebase-messaging-sw.js` fires as well and calls `showNotification` a second time. This degrades trust in the notification system and causes noticeable spam for active conversations.

## What Changes

- Change the Edge Function FCM payload (`supabase/functions/push/index.ts`) to be **data-only** — remove the `message.notification` block so Chrome does not auto-display a system notification and only the service worker's `onBackgroundMessage` handler renders one notification.
- Ensure the SW handler (`firebase-messaging-sw.js`, generated by `scripts/generate-firebase-sw.js`) still resolves title/body from the `data` payload (it already falls back to defaults, but `data.title` / `data.body` must now be populated explicitly).
- Add `title` and `body` fields to the `data` map emitted by the Edge Function so the SW has everything needed to build the notification without the removed `notification` block.
- Verify the foreground path (`PushNotificationProvider`) still works — it reads from `payload.data`, so it is unaffected, but confirm no code depends on `payload.notification`.

## Capabilities

### New Capabilities

_(none)_

### Modified Capabilities

- `push-notifications`: The "Supabase Edge Function Dispatch" and "Background Notification Rendering" requirements change to mandate **data-only FCM payloads** so background notifications are rendered exactly once by the service worker.

## Impact

- **Code**: `supabase/functions/push/index.ts` (payload shape), `scripts/generate-firebase-sw.js` (title/body read from `data`), regenerated `public/firebase-messaging-sw.js`.
- **Deployment**: Edge Function must be redeployed (`supabase functions deploy push`); users receive the new SW on next app load (skipWaiting is already enabled).
- **No database or schema changes.**
- **No client-side token logic changes.**
- **Risk**: Data-only messages on iOS PWA have platform-specific behavior, but the app currently targets Chrome/Edge web push where data-only messages work reliably. Android Chrome and desktop browsers will render notifications normally via the SW handler.
