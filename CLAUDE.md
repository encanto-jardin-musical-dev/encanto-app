## Architecture Overview

**Tech Stack:**
- Next.js 15 (App Router) with React 19 and TypeScript
- Supabase for backend (PostgreSQL, Auth, Real-time subscriptions)
- TanStack React Query for server state management
- Jotai for client state management
- HeroUI for component library with Tailwind CSS
- next-intl for internationalization

**Key Architectural Patterns:**
- **Authentication**: Supabase Auth with middleware-based session management (`src/middleware.ts`)
  - Middleware updates user session on every request
  - Server-side auth utilities in `src/utils/supabase/server.ts` and `src/utils/supabase/middleware.ts`
- **State Management**:
  - **Jotai** for client state: atoms in `src/lib/store/` (user.ts, feed.ts, messages.ts, common.ts)
  - **React Query** for server state: all API calls, caching, and synchronization
- **Data Fetching Pattern** (IMPORTANT):
  1. Define query functions in `src/queries/{domain}/` (e.g., `src/queries/users/get-user-profile.ts`)
  2. Create custom hooks in `src/hooks/` wrapping React Query (e.g., `UseGetUserProfileQuery.ts`)
  3. Use hooks in components for type-safe data access
- **Real-time**: Supabase real-time subscriptions for live messaging and feed updates
- **PWA**: Service worker with Firebase push notifications (`public/firebase-messaging-sw.js` auto-generated by `scripts/generate-firebase-sw.js`)

**Database Integration:**
- Typed Supabase client using generated types from `src/types/database.types.ts`
- Client creation pattern: singleton browser client in `src/utils/supabase/client.ts`
- Server-side utilities in `src/utils/supabase/server.ts` and `src/utils/supabase/middleware.ts`

**App Structure:**
- **Feed System**: Real-time messaging feed with group filtering (`src/app/feed/`)
- **Messaging**: Direct messaging between users (`src/app/messages/`)
- **Role-based Access**: Support for parents, teachers, administrators with different group permissions
- **Push Notifications**: Firebase integration with VAPID keys for web push

## Key Development Patterns

### Query and Mutation Pattern (CRITICAL)

**Always follow this pattern when adding new data operations:**

1. **Query Functions** (`src/queries/{domain}/`)
   ```typescript
   // src/queries/users/get-user-profile.ts
   import { supabase } from '@/utils/supabase/client';
   import type { Database } from '@/types/database.types';

   type Profile = Database['public']['Tables']['profiles']['Row'];

   export async function getUserProfile(userId: string): Promise<Profile | null> {
     const { data, error } = await supabase
       .from('profiles')
       .select('*')
       .eq('id', userId)
       .single();

     if (error) throw new Error(`Failed to fetch profile: ${error.message}`);
     return data;
   }
   ```

2. **Custom Hooks** (`src/hooks/`)
   ```typescript
   // src/hooks/UseGetUserProfileQuery.ts
   import { useQuery } from '@tanstack/react-query';
   import { getUserProfile } from '@/queries/users/get-user-profile';

   export function useGetUserProfileQuery(userId: string) {
     return useQuery({
       queryKey: ['user-profile', userId],
       queryFn: () => getUserProfile(userId),
       enabled: !!userId,
       staleTime: 5 * 60 * 1000, // 5 minutes
     });
   }
   ```

3. **Mutations** (same pattern with `Mutation` suffix in hook names)

**Database Query Guidelines:**
- Always use generated types from `src/types/database.types.ts`
- Handle errors explicitly - never ignore the `error` property
- Use RLS-aware queries - Supabase automatically filters based on authenticated user
- For complex operations, use database functions via `supabase.rpc()`
- Always validate user authentication before queries

**Component Organization:**
- Domain-specific: `src/components/{domain}/` (messages, feed, auth)
- Shared components: `src/components/common/`
- Follow HeroUI patterns for consistency

**Type Safety (NON-NEGOTIABLE):**
- Database types: Auto-generated in `src/types/database.types.ts` from Supabase schema
- Usage: `Database['public']['Tables']['table_name']['Row']` for read types
- Usage: `Database['public']['Tables']['table_name']['Insert']` for insert types
- Avoid `any` types - use proper TypeScript typing throughout

**Internationalization:**
- Translation files in `messages/` directory
- Configuration in `src/i18n/request.ts`
- Use `next-intl` hooks for all user-facing text

### Database Schema & RLS

**Key Tables:**
- `profiles` - Extended user info (links to `auth.users`)
- `children` - Student records
- `child_guardians` - Parent-child relationships
- `groups` - Classes/groups with teacher assignment
- `messages` - Direct and group messaging
- `attendance`, `daily_reports`, `tasks` - Educational features
- `subscriptions` - Web push notification subscriptions

**Row Level Security (RLS):**
- All tables have RLS enabled
- Policies use `auth.uid()` for user-specific access
- Messages: users can only access their own sent/received messages
- Groups: teachers can access their groups, parents can access their children's groups
- Use `get_user_groups(user_id, user_role)` database function for role-based group access

**Database Functions:**
- `get_user_groups(user_id, user_role)` - Returns groups based on user role
- `get_profiles_by_guardian()` - Returns teacher profiles for guardian's children
- `handle_new_user_registration()` - Auto-creates profile on signup
- `trigger_set_timestamp()` - Auto-updates `updated_at` fields

### Real-time Subscriptions

```typescript
// Subscribe to real-time changes
const subscription = supabase
  .channel('messages')
  .on(
    'postgres_changes',
    {
      event: 'INSERT',
      schema: 'public',
      table: 'messages',
      filter: `receiver_id=eq.${userId}`,
    },
    payload => {
      // Invalidate React Query cache or update state
      queryClient.invalidateQueries({ queryKey: ['messages'] });
    }
  )
  .subscribe();

// Always cleanup on unmount
return () => subscription.unsubscribe();
```

## Git Commit Guidelines

**IMPORTANT**: Always write commit messages in **English** using conventional commit format:
- Format: `<type>[optional scope]: <description>`
- Types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`
- Common scopes: `(auth)`, `(ui)`, `(api)`, `(db)`, `(config)`
- Use present tense, lowercase, no period: `feat(auth): add login validation`
- Breaking changes: Add `!` after type and `BREAKING CHANGE:` in footer

## Common Anti-Patterns to Avoid

❌ **Don't bypass the query/hook pattern** - Always use the established query → hook → component flow
❌ **Don't disable RLS** - Never use `disable row level security`
❌ **Don't ignore Supabase errors** - Always check and handle the `error` property
❌ **Don't use `any` types** - Use generated database types
❌ **Don't make raw SQL queries** - Use Supabase client methods or database functions
❌ **Don't forget real-time cleanup** - Always unsubscribe from channels on unmount
